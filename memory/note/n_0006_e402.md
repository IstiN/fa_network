# Note: n_0006_e402

dap hub migration phase 1 (2026-09-27): GCE VM `dap-hub-vm` (e2-micro free tier, us-central1-a, Debian 12, 30GB pd-standard) with static IP 104.198.37.115 (`gcloud compute addresses describe dap-hub-ip --region=us-central1`). Hub = static binary at ~/dap-hub (built from dap repo main, GOOS=linux CGO_ENABLED=0), systemd unit dap-hub.service (User=Uladzimir_Klyshevich, EnvironmentFile=/etc/dap-hub.env 0600, LimitNOFILE=1048576), HUB_ADDR=127.0.0.1:8080, data in ~/dap-data (channels.json+secrets.json migrated from gs://dap-hub-data). Caddy (apt) terminates TLS: /etc/caddy/Caddyfile = hub.fa1.dev → reverse_proxy 127.0.0.1:8080. Daily disk snapshots 04:00, 7d retention (resource-policy dap-hub-daily). PENDING at setup time: owner must repoint DNS hub.fa1.dev (external registrar, NOT Cloud DNS) from ghs.googlehosted.com to 104.198.37.115, then Caddy issues cert; Cloud Run dap-hub kept as rollback. Scaling path = vertical resize (set-machine-type), by design single-process. Anti-spam: channel creation gated to master-auth connections (dap@bd8950f, BREAKING), client-secret agents join only existing channels. GOAL issue: dap#4.
