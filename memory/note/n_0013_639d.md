# Note: n_0013_639d

fa_network fanet1/dap interop (инцидент 2026-10-25 РЕШЁН): relay-only подтверждён known-answer тестами (PR #14, internal/server/fanet1_test.go + fanet_interop_integration_test.go + testdata/fanet1_vectors.json сгенерированы и приняты эталонным mcp-bridge crypto.ts): envelope.id сохраняется как dap frame id, payload byte-identical app↔DAP на свежем post-#11 канале, обе стороны декриптуются. КОРЕНЬ был НА КЛИЕНТЕ (fah hub_fabric_repository): для приватных каналов слал RAW dap/1 (первый байт 0xA1, app ждал fanet1 0x01) вместо fanet1; «старый канал работал» потому что был PUBLIC showcase (raw JSON). Клиент добавил fanet1 seal/open + KAT против наших векторов; senderKey/whois НЕ нужен (fanet1 self-describing: 0x01||senderX||nonce||ct||tag; AAD dap1|envelope.id|channelId; HKDF salt=utf8(envelope.id), info=dap1/v1). Урок: сначала проверять версию кадра/формат payload, а не ключи или relay; keygen-мисматч тогда НЕ подтвердился (у агента были правильные ключи).
