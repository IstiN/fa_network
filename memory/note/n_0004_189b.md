# Note: n_0004_189b

fa_network ai-native auth contract (verified against LIVE prod logins 2026-09-26): ai-native.cloud is an IstiN/auth deploy (project dmtools-oauth-1749672403). Tokens are HS256 with the shared JWT_SECRET (SM auth-jwt-secret there; copied byte-identical to ai-native-478811 SM fa-network-ai-native-secret → env FA_NETWORK_AUTH_AINATIVE_SECRET — sha256-verified equal). Claims: iss="ai-native" (the jwtutil.Issuer CONST, NOT the host — an early fa_network build wrongly required the host and rejected every real token; accept-set is now "ai-native" + base host + empty iss + optional env FA_NETWORK_AUTH_AINATIVE_ISSUER), sub=email, userId, role, products. NO JWKS/RS256. fa_network resolves the locked display name from GET /api/auth/user (Bearer), 5-min cache, email fallback. Native client flow: GET /api/oauth-proxy/providers → POST /api/oauth-proxy/initiate {provider, client_redirect_uri, client_type, environment} → {auth_url,state,expires_in} → browser → client_redirect_uri?code&state → POST /api/oauth-proxy/exchange {code,state} → {accessToken,refreshToken,expiresIn,...}. Loopback redirect URIs always allowed; custom schemes (fa://) need OAUTH_ALLOWED_REDIRECT_URIS in the auth deploy (learn.ai submodule — owner action).
